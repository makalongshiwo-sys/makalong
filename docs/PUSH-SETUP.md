# 观潮远程提醒：无需厂商材料或 Google 服务

这版采用第三方开源 Android 应用使用的常驻连接方式。观潮 APK 自己保持 HTTPS 订阅、读取项目发布的公共行情事件、显示 Android 系统通知。无需安装额外推送 App、提交 vivo / OPPO 材料或配置 Google 项目。

## 手机上的操作

1. 安装本版 APK，在“提醒”页允许通知，点击“开启远程提醒”。
2. 点击“允许后台运行与锁屏联网”，允许系统的电池优化豁免；在 vivo / 一加应用管理中允许观潮后台耗电、锁屏联网及自启动。菜单名称随系统版本变化。
3. 查看连接状态和“最后云端读取”。成功后可以照常划掉最近任务卡片；不要求把观潮卡片锁在最近任务里。
4. 可以同时开启“实时盯盘”，获得更快的本地波动检查；两条渠道共用按币种冷却和通知去重。停止远程提醒会断开连接并移除其常驻通知。

声音、震动、横幅、锁屏展示在系统“行情与研究”通知分类设置。远程连接常驻通知是安静的；有符合所选类型和阈值的新事件时，使用高重要性行情通知分类。

## 已实现的链路

- 云端 GitHub Actions 约每 5 分钟读取 BTC / ETH / SOL 的 1h / 4h 已闭合 K 线、指标和短时波动。调度可能排队或延迟，不是秒级推送服务。
- 云端与 Android 共享纯 Java Market 指标模型，并读取相同长度的 500 条 K 线。UTC 周期、候选线与缺口重新预热规则一致。
- 独立 `guanchao-live-signals` 分支保存带来源时间的公共行情事件和检查覆盖情况；不修改研究报告，不含账户、个人持仓或设备令牌。初次部署建立基线，不补发旧闭合事件。
- 新事件通过 ntfy 公共主题发送一个 `refresh` 唤醒。APK 不能直接把通道中的文字变成行情通知；必须再次从本项目 HTTPS 数据接口读回、完整验证时间和事件字段。
- APK 使用可见的 `specialUse` 前台服务保持订阅、重连、定期补读、在正常系统回收时尝试恢复，并在用户已启用的情况下尝试开机恢复。它与有 6 小时时长限制的本地 dataSync 盯盘服务不同。

## 网络和系统的实际边界

代码不依赖 Google / VPN 服务。手机仍必须能够直接连接 `ntfy.sh` 及 GitHub 数据地址（优先 `raw.githubusercontent.com`，备用 `api.github.com`），不同地区、运营商的可达性需要实际检查；不能把国外公共服务写成“境内必然无 VPN 可用”。断线、资料过期或来源不足时显示实际状态，不使用历史价格伪造即时行情。若当地屏蔽这些地址，需要将消息服务及行情接口迁移到可直连的服务器；本版没有假装已经部署境内服务器。

标准 Android 移除最近任务不等同于强行停止。vivo / ColorOS 的“一键清理”是否同时终止受允许的前台连接，须在两台真机实测。厂商禁止自启动、彻底终止服务、系统强行停止、禁通知、离线或 Doze 网络限制都可能导致迟到或无法送达。源码不包含假装退出、静音播放、透明界面或无障碍保活。

Android 16 模拟器验证记录会随最终安装包交付：安装、同签名重装、任务移除、真实 HTTPS 连接与云端读回、仅在调试模拟器上的进程回收测试和用户停止。模拟器回执不能替代两台手机的送达结果。

## GitHub 参考

以下项目证明该连接模式不要求 FCM。观潮独立实现 Java 连接及行情检查，没有复制这些项目的 Kotlin 源码。

- [ntfy Android](https://github.com/binwiederhier/ntfy-android/tree/51730a0f06cebfad59f1b7bc0cb6d5c47082b032)：非 Google 版本、SubscriberService、可见前台连接、重连及后台电池设置。
- [Gotify Android](https://github.com/gotify/android/tree/211682fddee06bc1b53e9980c8ec9ad72409685b)：无需 FCM 的 WebSocket 通知连接和 `specialUse` 前台服务。
- [UnifiedPush connector](https://github.com/UnifiedPush/android-connector/tree/14427332043a46eb285676c97637f8842814a686)：开放推送协议，但需要发行器；本版直接内置订阅，避免额外安装 App。

后续 APK 更新必须复用最终交付版的同一私有签名。公开仓库仅保存公钥和加密恢复材料，不保存私钥。
